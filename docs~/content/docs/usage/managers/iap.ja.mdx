---

`IAPManager` は Unity IAP 5.4.1 の `StoreController` を使い、接続、商品取得、購入、未確定注文の再試行、復元を管理します。プレイヤービルドでは報酬の永続化が成功するまで注文を確定しません。

```csharp
var iap = ServiceLocator.Resolve<IAPManager>();
iap.AddProduct("com.mygame.coins_100", ProductType.Consumable);
iap.AddProduct("com.mygame.remove_ads", ProductType.NonConsumable);
iap.ReceiptValidator = new GameReceiptValidator();
await iap.Initialize();
```

## Editor Fake Store テスト

Unity Editor では `IAPManager` が Unity IAP の `fake` ストアを明示的に使用します。
Editor でのみ `ReceiptValidator` と `PurchaseProcessor` の両方が未設定でも Fake Store の注文を自動確定するため、実際の決済やバックエンド通信なしで購入ボタン、完了イベント、ポップアップの流れをテストできます。

この動作は `UNITY_EDITOR` の場合だけ含まれます。Android、iOS、その他のプレイヤービルドでは、購入を開始する前に領収書検証または報酬処理を設定してください。Editor の Fake Store 注文が実際の購入報酬として扱われることはありません。

Full Sample の `PurchasePopup` も Editor では検証コンポーネントなしで購入ボタンを有効にします。実際のビルドでは `Receipt Validator` フィールドにゲーム固有のサーバー検証コンポーネントを設定してください。

ゲーム側で `IIAPReceiptValidator` を実装し、認証済みプレイヤー、取引 ID、レシート、商品をサーバーへ送り、取引 ID を冪等キーとして報酬を保存してください。

```csharp
var result = await iap.PurchaseAsync("com.mygame.coins_100");
if (result.IsSuccess)
    Debug.Log("購入と報酬を確定しました。");
```

`Confirmed`、`Failed`、`Deferred`、`PendingFulfillment` の状態を確認できます。`RetryPendingFulfillmentsAsync()` は現在セッションの未確定注文を再試行し、`GetPendingListAsync()` はストアの購入履歴を再取得します。

Apple では `RestoreTransactionsAsync()` をユーザー操作の復元ボタンから呼び、`PurchaseRestored` で所有状態を更新します。
